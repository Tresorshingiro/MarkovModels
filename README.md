# Human Activity Recognition with a Hidden Markov Model

I recorded my own phone's motion sensor data and built a Hidden Markov Model (HMM) from scratch with NumPy to work out which activity was happening: standing, walking, jumping, or still.

## Results

Tested on 16 recordings the model never saw during training (82 windows, in 2 test files):

| Activity | Windows | Sensitivity | Specificity | Accuracy |
|---|---|---|---|---|
| Standing | 20 | 1.000 | 0.935 | 0.951 |
| Walking | 21 | 1.000 | 1.000 | 1.000 |
| Jumping | 20 | 1.000 | 1.000 | 1.000 |
| Still | 21 | 0.810 | 1.000 | 0.951 |
| **Overall** | **82** | | | **0.951** |

5-fold cross-validation across all 80 recordings gives 97.5% accuracy.

Still and Standing are the hardest pair to separate, and all 4 test errors are Still windows predicted as Standing.

## Data

| | |
|---|---|
| App | Sensor Logger |
| Phone | Samsung SM-A235F |
| Sensors | Accelerometer and gyroscope (x, y, z) |
| Sampling rate | About 102 Hz, resampled to 100 Hz |
| Recordings | 80 (20 per activity, about 10 s each) |
| Time per activity | Over 200 s |

## Method

1. **Clean:** align both sensors on a 100 Hz clock and trim 1 s from each end.
2. **Window:** cut each recording into 2.56 s windows (256 samples) with 50% overlap, giving 408 windows.
3. **Extract features:** compute 10 features per window, 6 from the time domain and 4 from the FFT.
4. **Normalise:** apply z-scores, using the mean and standard deviation of the training data only.
5. **Train:** calculate the starting parameters from the labels, then refine them with Baum-Welch until the log-likelihood per window improves by less than 0.0001.
6. **Decode:** use Viterbi to find the most likely sequence of activities.
7. **Evaluate:** train on recordings 1-16 of each activity and test on recordings 17-20.

## How to run

You need Python 3.12 or similar. On Windows, from the project folder:

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install numpy pandas matplotlib jupyter
jupyter notebook hmm_activity_recognition.ipynb
```

Then run all the cells in order. The notebook has to stay in the project root, because it finds `Data/` relative to where it runs. `Data/raw` is already included, so you don't need `extract_data.py` unless you are starting from new zips.

## Limitations

- The test data comes from the same phone, person and sessions as the training data, so the results may not hold for other people or phones.
- Each recording holds one activity. The activity changes in the training and test sequences come from joining recordings together, so the switching probabilities don't describe real behaviour.
- Baum-Welch lowered test accuracy from 100% to 95.1%, because it maximises likelihood rather than accuracy.
- A continuous recording on a new day, moving through all four activities, would be a stronger test.
